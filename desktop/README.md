# cut desktop

новый desktop-клиент для windows: tauri 2, rust, typescript, react + vite, tailwind css 4, локальные компоненты shadcn/ui на radix, motion, zustand и tanstack query.

```powershell
cd desktop
npm ci
npm run tauri dev
```

для разработки нужны node.js 22.12+ (или 24+), rust stable, microsoft c++ build tools и webview2 runtime. node нужен только для сборки; приложение не запускает node или flutter.

```powershell
npm test
cargo test --manifest-path src-tauri/Cargo.toml --lib
npm run build
npm run tauri build
```

установщик: `src-tauri/target/release/bundle/nsis/EditHub_2.3.1_x64-setup.exe`.

## совместимость

читаются существующие `~/.edithub/settings.json`, `google-drive.json`, `.edithub.json`, mac `.edithub-metadata.json` и `{name}.edithub`. неизвестные поля настроек и манифеста сохраняются. Flutter-клиент удалён; основная сборка и workflow переведены на tauri.

новые проекты: `{projectsFolder}/{year}/{MONTH}/{name}` с прежним набором папок. архив: `{icloudPath}/edithub/Videos`; также читаются старые `Videos` и `Edit Hub/Videos`. перенос публикует только завершённую копию и удаляет исходник после успеха. восстановление переносит папку обратно. это работа с папкой клиента iCloud; завершение локального копирования не означает завершения облачной синхронизации.

resolve открывается/экспортируется через сохранённый python bridge. требуется Resolve с доступным scripting API и `fuscript.exe` либо Python. перед сгрузкой Resolve-проекта выполняется свежий экспорт .drp; если он не удался, исходная папка остаётся на месте. поддержка premiere удалена; старые проекты с этим editor остаются видимыми, но не запускаются и не экспортируются.

## скачивания

- публичные файлы google drive: прямой endpoint, cookies и форма подтверждения больших файлов;
- публичные папки google drive: рекурсивное чтение embeddedfolderview без входа, с сохранением вложенной структуры;
- закрытые папки/файлы google drive: oauth с pkce, существующие flutter-токены, refresh и рекурсивный список через Drive API; для публичных папок также можно использовать API key;
- dropbox: официальное `dl=1`, сохранение `rlkey`, поддержка файлов и zip папок на www-хосте;
- поток на диск, прогресс, отмена ожидания заголовков/данных, ограниченные повторы, таймаут остановки потока;
- докачка только с ETag/Last-Modified и If-Range, иначе безопасный повтор с начала;
- существующие файлы не перезаписываются; ZIP проверяется на выход из папки и символьные ссылки, распаковывается в отдельную папку, оригинальный ZIP остаётся;
- прерванные при закрытии загрузки показываются как приостановленные с кнопкой повтора.

пароли dropbox, Google Docs/Sheets и Drive-ярлыки пока не поддерживаются. истёкшая сессия или недостаточные права показываются как ошибка, а не как успешная загрузка.

новому google-подключению нужен собственный OAuth client ID типа Desktop app с включённым Drive API. параметры вводятся в настройках; токены хранятся в прежнем локальном google-drive.json и не передаются React.

## проверка настоящего окна

`scripts/smoke.mjs` подключается к CDP только на localhost:9223 и отказывается менять проекты, если корень отличается от `desktop/.qa/projects`. debug-сборка поддерживает переменную `EDITHUB_CONFIG_DIR` для изолированного конфига; release её игнорирует. запусти debug-приложение с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223` и отдельными настройками в `.qa/config`, затем `node scripts/smoke.mjs`.

smoke-проверка: native IPC, создание проекта, структура папок, настоящая HTTP-загрузка с локального сервера, прогресс, React в webview, обе темы, сохранение темы после перезагрузки, нативная рамка, blur диалогов, доступность действий в узком окне и screenshots.

закрытие окна скрывает приложение в трей и оставляет скачивания работать. щелчок по значку возвращает окно; меню значка позволяет выйти.

## границы переноса

перенесены локальные проекты, создание, проводник папок, загрузки, настройки, google oauth, запуск resolve, сгрузка/восстановление, корзина. пока отсутствуют автообновление, пакетный экспорт всех Resolve-проектов и серверная синхронизация каталога.

установщик не подписан. живой oauth и экспорт в Resolve требуют отдельной проверки в пользовательском окружении. публичная папка пользователя проверена: найдено 293 файла в четырёх ветках, скачан JPEG 6 014 676 байт; также получено и проверено начало MP4/MOV из DRONE (5 691 байт), после чего загрузка намеренно отменена. полностью все исходники не скачивались. обычные HTTP-проверки используют локальный сервер.

источники протоколов: [tauri commands](https://v2.tauri.app/develop/calling-rust/), [dropbox dl=1](https://help.dropbox.com/share/force-download), [Drive downloads](https://developers.google.com/workspace/drive/api/guides/manage-downloads).


подхват google-ключей: настройки, вход и загрузчик используют один reader для `~/.edithub/google-drive.json`. поддерживаются исходные поля Flutter и snake_case-эквиваленты, UTF-8 с BOM. при запуске refresh token обновляет access token, а статус проверяется запросом к Drive API. секреты не передаются в UI. в настройках есть кнопка «Check connection»; при сетевой ошибке существующие ключи остаются на месте. проверка действующего пользовательского подключения через Rust успешно получила Drive API HTTP 200.

## Updates

Signed updates are checked at startup and every six hours
Settings ? EditHub ? Install and restart installs an available release after active operations finish

To publish: bump the version in package.json, package-lock.json, Cargo.toml, Cargo.lock and tauri.conf.json, then push a matching vX.Y.Z tag
GitHub Actions builds the installer and publishes latest.json and its signature
TAURI_SIGNING_PRIVATE_KEY is stored in repository Actions secrets, never in git
Local signing key backup: ~/.edithub-signing/edithub-updater.key ? preserve it for future releases
